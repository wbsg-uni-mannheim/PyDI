# Module 1: Knob 8 — Schema Naming Divergence

## Purpose

Header-only column renames via per-domain lookup tables. The simplest knob — establishes the script template pattern used by all subsequent knobs. Runs last in the canonical pipeline order but is implemented first for this reason.

## Spec References

- **Knob card:** [knobs/knob_08_schema_naming.md](../../knobs/knob_08_schema_naming.md) — full specification including the 4-rung naming ladder (descriptive → abbreviated → cryptic → anonymized), per-domain baselines, algorithm selection, anonymization seeding
- **Cross-cutting provenance:** [knobs/cross_cutting.md](../../knobs/cross_cutting.md) § "Per-value provenance" — column-scoped provenance records for header operations
- **SM test-set treatment:** [knobs/cross_cutting.md](../../knobs/cross_cutting.md) § "Test-set treatment" — SM mapping unchanged in S1 unless headers actively perturbed (Knob 8). Regenerated by composing `original_mapping ∘ inverse(rename_table)`
- **Target schema:** `usecases/companies/input/schemamatching/target_schema.json` — JSON Schema defining the canonical attribute names (id, name, website, founded, country, city, industry, assets, revenue, founders)
- **Existing SM mappings:** `usecases/companies/input/schemamatching/` — current source-to-target mappings that serve as the base for regeneration

## Per-Domain Baselines (from knob card)

| Domain | Baseline Level | Notes |
|---|---|---|
| Companies | At hard | Forbes abbreviated, DBpedia abbreviated/cryptic, FullContact anonymized |
| Games | At medium | All three in abbreviated/cryptic band |
| Music | At easy | All descriptive |

This means: companies-easy requires **rename-up** (anonymized→descriptive); music-hard requires **rename-down** (descriptive→anonymized).

## Files to Create

| File | Responsibility |
|---|---|
| `usecases_synthetic/scripts/apply_knob_08_naming.py` | CLI: `--domain`, `--level`. Loads source DataFrames, applies rename table from YAML, writes renamed DataFrames, regenerates SM mapping, writes provenance |
| `usecases_synthetic/config/knob_08_naming/companies.yaml` | Rename tables per source per column: `{dbpedia: {name: {descriptive: "company_name", abbreviated: "comp_nm", cryptic: "c_name", anonymized: "attr_1"}, ...}}`. Level→rung assignment per source |

## Config Structure (companies.yaml)

```yaml

  dbpedia:
    level_rung:

      medium: abbreviated

    columns:
      name:
        descriptive: company_name
        abbreviated: comp_nm
        cryptic: c_name
        anonymized: attr_1
      # ... per column
  forbes:
    level_rung:
      easy: descriptive
      medium: descriptive
      hard: abbreviated
    columns:
      # ...
  fullcontact:
    level_rung:
      easy: descriptive
      medium: cryptic
      hard: anonymized
    columns:
      # ...
```

## Algorithm (from knob card § "Algorithm selection")

1. Load per-domain rename table from YAML
2. For each source, look up the target rung for the requested level
3. Walk columns: replace header with the rung's variant from the table
4. Anonymization uses `stable_hash(domain, source, original_header) mod table_size` — deterministic, collision-detected at authoring time
5. Regenerate SM mapping: for each `(source_col → target_attr)` in the original mapping, replace `source_col` with its renamed variant; target side unchanged
6. Write provenance: one row per renamed column with `transform_fn ∈ {rename_descriptive, rename_abbreviated, rename_cryptic, rename_anonymized}`

## Acceptance Criteria

1. Companies easy: all 3 sources have descriptive headers matching target_schema.json field names
2. Companies hard: ≥1 source fully anonymized; no source descriptive
3. Provenance CSV has one row per renamed column with valid `transform_fn`
4. SM mapping file regenerated with updated LHS column names, RHS (target) unchanged
5. Cell values unchanged: diff of all values before/after is empty
6. `pytest usecases_synthetic/tests/test_knob_08.py -v` passes

## Follow-ups (post-S1, 2026-04-17)

Landed during S1 validation on `companies-small`. See [plans/validation/plan_s1_validation.md](../validation/plan_s1_validation.md#pre-ablation-fixes-applied-on-companies-small-2026-04-17).

1. **Orchestrator audit metric switched from row count to edit distance.** The `generate_variant --level all` monotonicity audit previously compared K8 provenance row counts across levels to assert naming divergence increased. This was confounded by upstream K3 drops (rows removed before K8 ran) and produced false failures. The audit now sums `rapidfuzz.distance.Levenshtein` between `original_value` and `new_value` across provenance rows (an order-insensitive proxy for header-divergence intensity) and checks that the sum is non-decreasing easy→medium→hard. Implementation: `_k8_naming_distance` helper in [scripts/generate_variant.py](../../usecases_synthetic/scripts/generate_variant.py); audit column renamed to `knob_08_naming_edit_distance`.
