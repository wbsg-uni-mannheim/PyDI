## Conventions

- **Process**: human owns git + branching; implementer (Claude) owns code/config/tests. All commands use `pydi-dev/`. No emojis in console output. NumPy-style docstrings. mypy strict. Preserve `DataFrame.attrs`.
- **No modifications to `PyDI/`** — new adapters, wrappers, prompts go under [usecases_synthetic/lib/](../../usecases_synthetic/lib/) or [third_party/](../../usecases_synthetic/third_party/). If `PyDI/` truly needs to change, stop and ask.
- **Source convention**: every source ships as `usecases/<domain>/input/data/<source>.csv` + `<source>_metadata.json` sidecar (post-2026-05-04). XML/JSON legacy at `data/old/` for reference only.
- **Reporting**: every stage delta narrates both committee `macro_f1` *and* best-member F1 (committee mean masks individual strong/weak members; best-member is the user-attainable ceiling). EM primary surface: `f1_vs_test` closed-set (with `f1_vs_val` as a learned-matcher overfit diagnostic). `f1_vs_test_gold` is benchmarking only, never a difficulty surface.
- **Terminology** (2026-05-06): use *train / val / test* sets, not "gold". `pool` / `pooled_positives` is the cross-evidence union; not a gold standard. Both fusion validation + test entities are protected at every value/entity-mutating knob (K2, K4, K1, K3, K5, K6, K10).
- **LLM model**: K2 hard + K4 easy default `gpt-5.4-mini`. Before any K2/K4 run (R6.1, R6.2, R7.4), ask the user whether to bump to `gpt-5.4` — `model_id` is part of the cache key so bumping invalidates the LLM cache. R3 pool adjudicator is locked to `gpt-5.4`, not subject to the prompt.
- **Committee tuning convention** (2026-05-08): every committee gets a hyperparameter sweep with user-approved grid before R6.1 freezes baselines. Pattern: Claude proposes grid + cost → user signs off → sweep runs → winners locked → re-smoke.
